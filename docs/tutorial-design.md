# 首战情境式教程设计

## 1. 目标与边界

教程嵌入第一章战斗节点 `square-battle`（“圣辉广场危机”）的第一回合，不创建独立教学关。玩家在真实战况中完成一次“观察信息 → 选择单位 → 移动 → 阅读结果 → 判断敌方意图 → 结束我方阶段 → 观察敌方执行”的闭环。

教程必须遵循正式规则：棋盘为 8×8；我方阶段由 `phase === "player"` 表示；单位默认移动范围为曼哈顿距离 3 格；生命或信念任一归零即失去战斗能力；敌方意图来自 `enemyIntents`；结束阶段调用 `endPlayerTurn`，敌方统一执行预告动作后进入下一回合。教程层不得复制、修改或伪造 `BattleState`，也不得绕过 `moveUnit`、`attackUnit`、`endPlayerTurn`。

体验目标：

- 90 秒内让首次玩家理解可行动单位、3 格移动、生命/信念、敌方意图、我方阶段与结束阶段。
- 教学提示采用棋盘锚点、高亮和常驻小卡片，不使用连续模态弹窗。
- 允许随时跳过，之后可在战斗帮助入口重看；教程失败不会污染战斗状态。
- 不增加依赖，沿用现有 DOM、CSS、Three.js 命中检测和浏览器存储能力。

## 2. 状态机

建议状态联合类型：

```ts
type TutorialStep =
  | "intro"
  | "select-unit"
  | "move-three"
  | "read-vitals"
  | "read-intent"
  | "end-phase"
  | "observe-enemy"
  | "complete";
```

教程状态只记录引导进度，不记录战斗数据。每次战斗状态变化后，先按 `BattleState` 渲染，再根据完成条件推进教程。推进必须幂等：同一状态重复同步不能跳过两步。除明确标注外，提示卡提供“跳过教程”，不提供遮挡棋盘的“下一步”；完成条件由真实操作触发。

### 七步定义

| 步骤 | 触发条件 | 中文文案 | 允许操作 | 暂时禁止/拦截 | 完成条件 |
|---|---|---|---|---|---|
| 1. 战况与我方阶段 `intro` | 首次进入 `square-battle`，`round === 1 && phase === "player"`，且未完成/跳过教程 | **先稳住广场。** 现在是“第 1 回合 · 我方阶段”。三名同伴可以各行动一次；敌人会在你结束阶段后统一行动。 | 查看棋盘、HUD、目标与单位信息；点击“开始指引”或跳过 | 棋盘行动与结束阶段；不冻结镜头浏览 | 点击“开始指引”。提示卡应为非模态，开始按钮只是明确教学起点，不改变战斗状态 |
| 2. 选择单位 `select-unit` | 步骤 1 完成，仍为我方阶段 | **先选择一名同伴。** 点击带圆形我方底座、且尚未行动的单位。选中后会显示她能到达的位置。 | 选择任一 `team === "player" && isActive && !acted` 单位；取消并重选 | 敌方单位、已行动/失去战斗能力单位、结束阶段；点击无效对象只给轻量反馈 | 当前选择指向合法我方单位，且合法移动格已显示 |
| 3. 移动三格 `move-three` | 已选中合法我方单位 | **向火线推进。** 亮起的格子都可到达；一次最多移动 3 格。请选择与起点曼哈顿距离恰好为 3、未被占用的高亮格。 | 取消后重选其他合法单位；点击合法三格目的地 | 距离 0–2 格仅提示“这一步请尝试完整的 3 格移动”；超出 3 格、棋盘外、占用格按正式失败原因反馈且不改状态；攻击与结束阶段 | `moveUnit` 返回 `ok === true`，同一单位位置变化的曼哈顿距离为 3，且该单位 `acted === true` |
| 4. 阅读生命与信念 `read-vitals` | 步骤 3 的成功状态已渲染 | **看一眼队伍状态。** 生命代表承受伤势，信念代表继续战斗的意志；任意一项归零，单位都会退出战斗。刚行动的同伴本回合不能再次行动。 | 查看刚行动单位卡；查看其他单位；键盘/触摸聚焦生命、信念说明 | 不额外限制合法战斗操作，但若玩家先做了其他合法动作，教程仍停留并保持提示 | 展开或聚焦任一单位卡中的生命与信念区域；无展开式 UI 时，二者进入视口且提示卡停留至少 1.5 秒即可 |
| 5. 阅读敌方意图 `read-intent` | 步骤 4 完成且 `enemyIntents.length > 0` | **敌人已经亮明下一步。** 箭头表示移动；武器与目标线表示攻击。攻击还会标明削减生命或信念。意图会在你结束我方阶段后执行。 | 选中/聚焦任一敌方意图；继续指挥未行动单位；查看目标单位 | 不禁止其他合法我方行动；结束阶段按钮保持可见但首次点击先将焦点引到意图，不执行 | 玩家聚焦/点击任一意图，或意图详情在视口中持续 1.5 秒；必须读取真实 `enemyIntents`，不得用固定示例 |
| 6. 结束我方阶段 `end-phase` | 步骤 5 完成，`phase === "player"` | **决定何时交出主动权。** 你仍可让其他同伴行动；准备好后，点击“结束阶段”。敌方将统一执行刚才预告的行动。 | 所有正式合法我方行动；点击结束阶段 | 无额外禁止；若已进入胜利/失败则直接结束教程 | 玩家点击“结束阶段”，实际调用 `endPlayerTurn`；记录调用前的 `round`、单位状态与意图摘要用于下一步核对 |
| 7. 观察敌方执行 `observe-enemy` | `endPlayerTurn` 开始处理；界面出现敌方阶段反馈或执行动画 | **预告正在兑现。** 敌方会按意图依次移动或攻击；执行完毕后，所有存活同伴可再次行动。 | 观察；在动画结束后继续游戏；跳过动画仅缩短表现 | 敌方执行期间禁止棋盘指令和重复结束阶段，防止并发输入；不阻止帮助/跳过教程 | 状态进入 `round === 上一步 round + 1` 且 `phase === "player"`，或进入 `victory/defeat`。校验意图执行结果后标记 `complete`，显示一次非模态提示：“第 2 回合开始。你已掌握战斗节奏。” |

步骤 3 的“三格”是教程目标，不改变正式 `moveRange`。若关卡布局中不存在合法的恰好三格空位，教程自动降级为“移动到任一最远合法格”，文案显示实际距离；该情况应被关卡数据验收视为配置错误而非正常路径。

## 3. 操作限制原则

- 限制只存在于教程控制层，并必须在调用规则函数前完成；被拦截的输入不得改变 `BattleState`。
- 正式规则拒绝的操作展示短暂原位反馈，并直接使用 `ActionResult.reason` 的中文映射。例如：“目标超出移动范围”“该位置已被占用”“该单位本回合已经行动”。
- 从步骤 4 起尽量不锁操作，让玩家自然继续战斗；教程依据观察事件推进，不要求连续点击“下一步”。
- `phase !== "player"` 时所有我方指令禁用；`victory/defeat` 优先于教程状态，立即停止教程输入限制。
- 高亮必须同时使用颜色、轮廓/形状与简短标签，不能只靠颜色表达敌我、可达或意图。

## 4. 跳过、重看与存储

使用版本化键名，避免未来教程调整被旧值永久跳过：

```text
localStorage["goddess-fall:tutorial:first-battle:v1"]
```

值为 JSON：

```json
{ "status": "completed", "completedAt": "2026-07-18T00:00:00.000Z" }
```

或：

```json
{ "status": "skipped", "skippedAt": "2026-07-18T00:00:00.000Z" }
```

- 首次进入首战且键不存在时自动启动。
- “跳过教程”立即解除教程限制，但不改动当前战斗状态，并写入 `skipped`。
- 步骤 7 正常完成后写入 `completed`。教程中途刷新不保存具体步骤；恢复后根据当前战斗存档重启到最安全的可满足步骤，若战斗本身从头开始则教程也从步骤 1 开始。
- 战斗帮助入口提供“重看首战教程”。点击后仅清除内存中的教程状态并从适配当前战况的步骤开始，不必删除历史标记；若用户明确选择“以后再次自动提示”，才删除该键。
- `localStorage` 不可用、写入失败或 JSON 损坏时静默退化为本次会话内存状态，不阻断战斗；损坏值视为未完成。

## 5. 展现与可访问性

### 桌面

- 提示卡固定在棋盘边缘，不覆盖当前目标单位、目的格、敌方意图或“结束阶段”按钮。
- 用一条细引导线连接提示卡与目标；目标变化后重新定位。卡片包含“步骤 n/7”、一句主文案、可选补充说明和跳过入口。
- 键盘焦点按教学目标移动，但不得从玩家正在操作的棋盘元素上强制抢焦点；提示卡使用 `aria-live="polite"`，阶段切换和错误反馈不可同时播报。

### 移动端

- 320px 起可用。提示卡收纳为底部非模态抽屉，最大高度不超过可视区 32%，关键动作按钮保持在安全区之上。
- 步骤 2、3 使用点击选择与点击落点，不依赖 hover；合法格至少 44×44 CSS px 的触控区域。
- 步骤 5 的意图详情可轻触展开，再次轻触或向下滑收起；结束阶段按钮始终可见，不要求滚动侧栏。
- 软键盘、横竖屏切换、地址栏伸缩后重新计算锚点；教程状态不回退。

### `prefers-reduced-motion`

- `reduce` 时禁用提示卡滑入、目标脉冲、引导线流动、棋子补间和阶段横幅扫入；改用立即显示、2px 静态轮廓和文字状态。
- 敌方执行仍需按逻辑顺序呈现，但可零时长更新并逐条刷新战报；步骤 7 的完成条件只依赖状态，不依赖 `animationend`。
- 默认动效下也不得让提示卡阻塞输入；单次提示过渡建议不超过 200ms。

## 6. 失败与恢复

- 非法点击：保持当前步骤，短暂标记错误目标并说明原因；不重置选择之外的战斗状态。
- 选中被取消或目标单位因外部状态变化失效：回到步骤 2，重新计算合法单位与可达格。
- 步骤 3 的选中单位已经 `acted`：清除教程选择并回到步骤 2，不篡改 `acted`。
- `enemyIntents` 为空：若战斗已结束则完成教程；否则重新从 `BattleState` 同步一次。仍为空时隐藏步骤 5 的限制并允许结束阶段，同时记录诊断事件。
- 结束阶段执行中刷新/切后台：恢复后依据 `round` 与 `phase` 判断。新一轮我方阶段直接完成步骤 7；敌方阶段则保持只读等待；绝不重复调用 `endPlayerTurn`。
- 胜利或失败发生在任一步：移除所有教程锁与高亮。胜利写入 `completed`；失败不写完成标记，并在“从战斗前重新开始”后重新提供教程。
- 渲染层异常或 WebGL 降级：教程不得遮挡错误/重试界面；重试成功后从当前 `BattleState` 重新推导步骤。

## 7. 事件与实现接线

建议教程控制器只订阅以下语义事件：`battle:ready`、`unit:selected`、`action:resolved`、`vitals:viewed`、`intent:viewed`、`phase:end-requested`、`battle:state-synced`、`battle:finished`。事件载荷只传 ID、动作结果和前后状态摘要；规则判定仍来自 `game/battle.ts`。

为便于稳定测试，可给关键元素增加不影响样式的属性：

- `[data-tutorial-step]`：当前提示卡及其步骤名。
- `[data-unit-id]`、`[data-team]`、`[data-acted]`：单位交互目标。
- `[data-cell-x] [data-cell-y] [data-reachable]`：棋盘格命中层。
- `[data-vital="health|faith"]`：生命/信念。
- `[data-enemy-intent] [data-intent-kind]`：真实意图条目。
- `[data-action="end-phase"]`：结束阶段按钮。

这些属性只暴露已有界面状态，不创建第二套规则数据源。

## 8. Playwright 验收

测试应使用确定性的首战种子/关卡数据，并在每例前清理上述 localStorage 键。避免用固定等待判断完成，优先等待状态属性和 HUD 文本。

1. **首次启动与非模态性**：进入 `square-battle` 后看到 `intro`、步骤 1/7、“第 1 回合 · 我方阶段”；目标与棋盘仍可查看，页面没有连续 modal/dialog 栈。
2. **选择合法单位**：开始指引后，敌方与失去战斗能力单位不可推进；选中未行动我方单位后进入 `move-three`，合法可达格出现。
3. **严格三格移动**：点击 2 格目的地不调用/不提交移动，状态位置不变；点击恰好 3 格空位后位置改变、`acted` 为真、进入 `read-vitals`。
4. **生命/信念规则说明**：单位卡同时显示生命与信念及“任一归零即退出战斗”的可访问文本；浏览该区域后进入 `read-intent`。
5. **真实敌方意图**：意图 UI 数量与 `BattleState.enemyIntents` 一致，移动/攻击种类、目标、伤害类型与数值一致；查看任一条后进入 `end-phase`。
6. **结束阶段闭环**：点击结束阶段仅调用一次 `endPlayerTurn`；敌方按预告执行；随后 `round` 增加 1、`phase` 回到 `player`、存活我方 `acted` 全部重置，教程进入 `complete`。
7. **跳过与重看**：任一步跳过后所有教程限制立即解除并写入 `skipped`；刷新不自动出现；从帮助入口重看时可在当前战况启动且不改 `BattleState`。
8. **失败恢复**：对超距格、占用格、重复行动发起输入，均显示明确反馈且状态不变；敌方阶段刷新不会重复执行；战斗失败后重开可重新教学。
9. **移动端**：在 320×568 与 390×844 视口完成七步；无横向溢出，底部提示不遮挡结束阶段，所有主要触控目标至少 44×44 CSS px。
10. **减少动态效果**：以 `reducedMotion: "reduce"` 运行完整流程；无依赖动画结束的超时，静态高亮与阶段文本均存在，步骤 7 正常完成。
11. **持久化降级**：模拟 localStorage 抛错和损坏 JSON，教程仍可完成且战斗无异常。
12. **回归**：教程完成或跳过后，移动、攻击、结束阶段、敌方意图刷新、生命/信念归零退场及胜负跳转均与无教程路径一致。

完成定义：以上用例通过，`npm test`、`npm run check`、`npm run build` 保持通过；无新运行时依赖；首战从剧情节点进入、跳过教程和重看教程三条路径均可完成完整战斗。
